# M5 源码来源与配对基线协议修正

## 1. 为什么必须修正

稳健反馈实验结束后，对每个成功补丁进行了人工结构检查。检查发现两个不能忽略的
有效性问题。

### 1.1 Chardet 试验副本没有被实际导入

Chardet 使用 `src/chardet/` 目录布局。旧运行器只把试验仓库根目录加入
`PYTHONPATH`，Python 因此找不到试验副本中的包，转而加载隔离环境中已安装的原始
Chardet：

```text
D:\hustagent\work\candidate-sources\chardet-main\src\chardet\__init__.py
```

这意味着测试和工作负载没有执行 Agent 修改的代码。旧 Chardet 结果无论数值是否
好看，都不能证明补丁正确或更快。

处理方式：

- 所有旧 Chardet 正式运行保留原始文件，但写入 `exclusion.json`；
- 汇总结果中明确列为 `excluded_invalid_import_path`；
- Chardet 项目上下文固定 `import_subdir = "src"`；
- 每次实验开始后先导入目标模块，并检查 `module.__file__` 是否位于本次试验副本；
- 导入来源不正确时，实验在 Agent 修改前直接失败。

修正后的预检实际返回：

```text
D:\hustagent\work\...\chardet-run-01\src\chardet\__init__.py
```

### 1.2 计时通过不代表候选真的并行

稳健 Radon 的一条候选通过测试、输出和性能阈值，正式计时约为 1.110×。但补丁
只插入了重复类定义，没有引入线程、进程或其他并行执行结构。它不是有效并行化，
只能说明运行时间会随机器状态波动。

处理方式：

- 从补丁的新增代码中检查显式并行结构，例如 `ProcessPoolExecutor`、
  `ThreadPoolExecutor`、`multiprocessing.Pool`、任务提交或映射调用；
- 没有并行结构的候选记为 `non_parallel_candidate`，即使计时超过阈值也不能接受；
- 该检查只证明补丁引入了并发机制，不单独证明它有效；最终仍需测试、输出和端到端
  配对性能共同验收。

### 1.3 历史串行时间不能替代本轮对照

早期实验把此前测得的串行中位数写入项目上下文。重新测量未修改 Radon 时，5 次
时间从 12.822 秒到 14.127 秒，中位数为 13.697 秒。这个范围足以让约 5%～10%
的小幅“提升”受到运行阶段和系统负载影响。

处理方式：

- 最终实验不再使用 `--skip-baseline`；
- 每个独立 Agent 运行先在同一个试验副本、同一环境中测量串行基线；
- 串行基线先预热 1 次，再运行 5 次取中位数；
- 现场中位数和输出哈希写入本轮 Agent 上下文；
- 候选反馈采用预热 1 次、运行 3 次的中位数；
- 最终候选仍独立预热 1 次、运行 5 次，并除以本轮现场串行中位数。

这种方式还不是严格的交替配对计时，较长 Agent 运行期间系统状态仍可能变化；该项
会写入局限性。但它比跨阶段复用一个历史时间更可靠。

## 2. 最终验收链

最终候选必须依次通过：

1. **导入来源门控**：实际运行的是本轮试验副本；
2. **源码证据门控**：修改引用当前源码片段和哈希；
3. **语义契约**：修改前明确状态、顺序、错误、序列化和后端约束；
4. **完整测试门控**：项目功能测试通过；
5. **输出门控**：注册工作负载输出与本轮串行基线一致；
6. **并行结构门控**：补丁确实引入可执行并行结构；
7. **稳健收益门控**：现场配对加速比至少为 1.05×；
8. **安全回退**：轮数结束仍不合格时恢复原串行源码。

## 3. 结论状态

- “旧 Chardet 结果无效”是已验证事实，证据为模块实际导入路径；
- “无并行结构的 Radon 补丁不能算有效并行化”是按预先目标定义作出的必要纠正；
- “现场配对稳健反馈能否提高最终成功率”仍是待验证假设，必须用修正后的正式重跑
  决定，不能沿用旧数值。
