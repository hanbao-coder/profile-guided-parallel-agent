# FIFO 与通信感知关键路径 DAG 调度实验

## 定位

这是一个确定性的同构 Worker 列表调度模型，用于验证调度启发式，不是真实 Ray
集群运行时间。真实多进程代码、配置搜索和任务融合实验已在其他实验中完成。

## 方法

### FIFO

就绪任务按照配置文件中的原始顺序调度。

### 通信感知关键路径优先

对任务计算 upward rank：

\[
rank(v)=t_v+\max_{u\in succ(v)}(c_{v,u}+rank(u))
\]

其中 \(t_v\) 是任务计算时间，\(c_{v,u}\) 是跨 Worker 时的通信估计。就绪任务
按 rank 从高到低处理；每个任务选择预计最早完成的 Worker，同一 Worker 上的
依赖边不产生通信成本。

这里的 rank 是调度优先级，不是实际 makespan 的理论下界。

## 测试图

### 计算关键路径图

一条包含三个 0.55 秒任务的长链，与三个 0.32 秒旁支竞争两个 Worker。FIFO
先调度旁支，可能延迟长链。

### 通信关键路径图

一条计算较轻但边通信估计为 0.40 秒的链，与两个低通信旁支竞争。通信感知 rank
优先保持高通信链连续推进。

## 结果

| 图 | 策略 | Makespan | 相对 FIFO | Worker 空闲比例 | 跨 Worker 通信 |
|---|---|---:|---:|---:|---:|
| 计算关键 | FIFO | 2.18 | 1.000x | 35.6% | 0.04 |
| 计算关键 | 关键路径 | 1.85 | **1.178x** | **24.1%** | 0.06 |
| 通信关键 | FIFO | 0.98 | 1.000x | 39.8% | 0.04 |
| 通信关键 | 关键路径 | 0.78 | **1.256x** | **24.4%** | 0.08 |

![DAG 调度对比](assets/dag_scheduling_formal_20260729/dag_scheduling_comparison.png)

关键路径策略的总跨 Worker 通信量没有必然更低；本实验的收益来自优先推进会限制
最终完成时间的链，并把链上 0.40 秒大通信边保持在同一 Worker。表中的剩余跨
Worker 通信来自低成本旁支。

## 局限

- 任务耗时和通信成本来自配置，不是在线预测器；
- 当前使用 append-only 同构 Worker 列表调度，不支持时间槽插入；
- 不包含故障、资源异构、抢占和动态任务生成；
- 只覆盖两张合成 DAG；
- 后续需要在 Linux/Ray 或 Maze 环境验证真实调度效果。

版本化调度表和完整时间线位于 `docs/data/dag_scheduling_20260729/`。
