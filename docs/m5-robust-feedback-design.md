# M5 稳健性能反馈消融设计

## 1. 实验现象

单次性能反馈组完成 6 次正式运行后，出现 4 个被快速反馈判为有效的候选。它们的
快速加速比与正式加速比分别为：

| 项目与运行 | 单次快速反馈 | 正式 5 次中位数 | 差值（正式 - 快速） |
|---|---:|---:|---:|
| Chardet-1 | 1.441× | 1.129× | -0.312 |
| Chardet-2 | 1.390× | 1.124× | -0.266 |
| Chardet-3 | 1.437× | 1.085× | -0.352 |
| Radon-1 | 1.141× | 0.945× | -0.196 |

4 个快速估计都高于正式复测。其中 Radon 候选在快速反馈阶段超过 1.05×，但正式
复测发生约 5.5% 的性能退化。这说明执行反馈不仅要“真实运行”，还需要控制计时
波动；否则 Agent 可能围绕一次偶然结果做错误决策。

## 2. 待验证假设 H4

> 与单次计时相比，在反馈阶段加入一次预热，并对三次运行取中位数，可以减少
> 错误接受性能退化候选，同时保留可重复的真实加速候选。

这个假设可以被实验否定。例如，若稳健反馈仍接受 Radon 退化候选，或把 Chardet
的真实加速全部拒绝，则当前测量方式没有达到预期。

## 3. 唯一改变

两组使用相同：

- DeepSeek 模型与温度；
- 12 轮模型调用上限和 4 轮修改上限；
- 源码锚点、语义契约、自动正确性门控和安全回退；
- 项目版本、硬件、输入、测试和 1.05× 接受阈值；
- 最终正式性能测试（预热 1 次、重复 5 次）。

唯一变化是 Agent 每轮看到的性能反馈：

| 组别 | 反馈预热 | 反馈正式运行 | 决策值 |
|---|---:|---:|---|
| F1：单次反馈 | 0 | 1 | 该次时间 |
| F3：稳健反馈 | 1 | 3 | 三次中位数 |

## 4. 正式实验

- 项目：Radon、Chardet；
- 每个项目每组 3 次独立 Agent 运行；
- F1 已完成，F3 在本设计冻结后开始；
- 不复用上一组生成的补丁或模型回答；
- 每次从固定 commit 的干净副本开始；
- 所有失败、回退和成功运行都进入统计。

主要指标：

1. 有效并行化次数；
2. 正确候选次数；
3. 性能退化次数；
4. 安全回退次数；
5. 反馈加速比与正式加速比的绝对误差；
6. Agent 调用次数、Token 和额外执行时间。

当前只提出假设，F3 真实运行结束前不写结论。
