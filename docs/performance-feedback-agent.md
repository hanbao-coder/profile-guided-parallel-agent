# 性能反馈 Agent：首轮消融

实验日期：2026-07-29

## 研究问题

只验证“代码能运行、输出正确”是否足以完成自动并行化？

首轮实验使用 Tiny Tasks。该任务满足显式数据并行契约，但每个数据项计算量
极小，进程启动和任务调度开销容易超过计算收益。

## 三组方法

| 方法 | 运行错误反馈 | 正确性反馈 | 性能反馈 | 允许串行回退 |
|---|---:|---:|---:|---:|
| One-shot | 否 | 否 | 否 | 否 |
| Correctness feedback | 是 | 是 | 否 | 否 |
| Performance feedback | 是 | 是 | 是 | 是 |

性能反馈组执行以下步骤：

1. 串行与并行候选各运行 3 次；
2. 使用固定随机种子打乱两种方法的执行顺序；
3. 比较端到端时间中位数；
4. 只有加速比达到 1.05 倍才保留并行；
5. 否则将实测时间、任务数、Worker 与 Chunk 反馈给性能控制器；
6. 控制器可调整配置或回退串行。

## Tiny Tasks 结果

| 方法 | 候选正确 | 并行候选加速 | 最终选择 | 回退后有效加速 |
|---|---:|---:|---|---:|
| One-shot | 是 | 0.45x | 并行 | 0.45x |
| Correctness feedback | 是 | 0.46x | 并行 | 0.46x |
| Performance feedback | 是 | 0.47x | 串行 | 1.00x |

![Tiny Tasks 性能反馈消融](assets/agent_ablation_tiny.png)

这组结果说明：一次性生成和正确性反馈都可能保留“语义正确但性能有害”的
候选。加入性能反馈后，Agent 根据三次重复测量识别到并行候选只有约 0.47 倍
加速，最终回退串行。

## 正向案例

Prime Count Large 使用相同性能反馈协议：

- 串行端到端中位数：约 0.598 秒；
- 并行端到端中位数：约 0.337 秒；
- 端到端加速：约 1.78 倍；
- 最终选择：保留 4 Worker / 4 Chunk 并行。

因此当前 Gate 不是“一律回退”，而是能够区分有收益与无收益任务。

## 分层模型路由

| 阶段 | 模型 | 思考模式 | 原因 |
|---|---|---|---|
| 依赖与语义分析 | deepseek-v4-pro | 开启 | 影响并行安全 |
| 结构化计划整理 | deepseek-v4-flash | 关闭 | 任务明确、节约 Token |
| 错误修复 | deepseek-v4-pro | 开启 | 需要结合运行反馈推理 |
| 性能优化/回退 | deepseek-v4-pro | 开启 | 影响最终效率结论 |
| 文档排版与常规检查 | 不调用或 Flash | 关闭 | 优先使用本地确定性工具 |

模型调用日志记录阶段、模型、思考模式、输入/输出/总 Token。API Key 不进入
日志或实验产物。

路由冒烟测试中，关闭 Flash 计划阶段思考后，该阶段 completion tokens 为
98；此前一条开启默认思考的代表性计划调用为 884。两次输入并非严格相同，
因此不能作为正式节省比例实验，但足以验证关闭常规阶段思考能够显著减少
无必要的推理 Token。后续正式实验将同时报告质量与 Token，避免只追求低成本。

## 当前边界

- Tiny Tasks 只有一次完整三组消融，尚需多个任务和多次独立模型运行；
- One-shot 与 Correctness 当前各测 1 次候选，正式实验需统一为 3～5 次；
- 性能回退恢复到串行基线，并不等于产生了额外加速；
- 当前运行后端是 Windows multiprocessing，不可写成 Ray 性能结论。
